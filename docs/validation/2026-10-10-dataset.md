## 实际问题、修复和复测

首轮 `pcg_diversity_v1` 在建图时出现 `Asset exists ... /Graph`。根因是 UE 建图/保存操作会嵌套推进 Slate，批量 runner 尚处于 `next_scene` 时重入同一 tick。外层随后仍完成了首场景 6 帧，所以错误状态与后续采集状态混杂。

修复：在进入 UE API 前切到 `preparing_scene`，已结束任务不再推进，finish 幂等；切图保持在后续 tick。新增模拟资产操作内部再次调用 tick 的回归测试。没有在正在采集时热重载；待首场景完成、解除活动任务、地图保存后加载修复，使用独立 v2 计划重跑完整矩阵。v1 保留作故障证据，不作为最终完整数据集。

调用 `runpy.run_path` 的导入只留在返回字典，不自动进入 UE 控制台全局；首次续跑控制台少了 `import capture_dataset`，出现 NameError，未触发采集。补上显式导入后完成了 6 场景全部跳过的续跑验证。

离线测试覆盖：配方多样性/可复现性、输入拒绝、类别 ID 唯一性、分组/PCG 变体共享底图、冻结配置、相机光学轴、损坏产物续跑、路径越界、非法 MASK、Slate 重入、射线平行/背向情况。损坏文件后重新采集的状态机通过 mock 测试，本轮没有破坏最终真实 PNG 做故障注入。没有声称完成真实引擎中断/崩溃恢复测试。

最终 `python -m pytest -q`：**331 passed, 2 skipped**；跳过的是现有 Windows 符号链接权限测试。`git diff --check` 通过。
